# Access matrix

This table describes the intended scientific access boundary. GitHub collaborator roles are handled separately.

| Material | Project Lead | Branch A | Branch B | Faculty Advisor |
| --- | --- | --- | --- | --- |
| Shared project repository | Access | Access | Access | Access |
| Branch A private repository | Access | Access | No access | Only if needed for a scheduled verification |
| Development data | Access | Produce | Access | Access as needed |
| Calibration observables | Access | Produce | Access | Access as needed |
| Blind-validation observables | Access | Produce | Access | Access as needed |
| Locked-test observables | Access after authorization | Produce after authorization | Access after protocol lock | Access as needed for verification |
| Sealed ground truth | Custodial access | Produce | No access before approved release | Only under the approved verification/release process |
| Blind or locked Branch B scientific outputs | Access for governance without unblinded truth | No access before the relevant Branch A freeze | Produce | Review only at the scheduled gate |

Restricted material should not be copied into the shared repository for convenience. Access follows the current data tier, freeze status, and release authorization.
